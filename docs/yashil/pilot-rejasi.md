| Сана | 30.10.2026 |

Режадаги муддатлар, иштирокчилар ва ташкилот номлари — **таклиф**. Улар буюртмачи билан келишилгач тўлдирилади ва 9-бўлимда тасдиқланади.

---

## 1. Мақсад ва қамров

### 1.1 Мақсад

ТЗ §19.2 бўйича ишчи муҳитга ўтишдан олдин:

1. Маълумотномалар текширилади: ташкилотлар, маҳаллалар, хўжалик бириктиришлари, уюшма йўналишлари, каталог, иш кунлари календари, бошланғич омбор қолдиқлари.
2. Камида битта маҳалла, битта ўрмон хўжалиги, Яшил боғларни ташкил этиш ДМ, маҳаллалар уюшмаси ва кузатувчи иштирокида **тўлиқ занжир** синовдан ўтказилади (ТЗ §1.2):
   маҳалла қораламаси → имзоланган буюртманома → уюшма текшируви → етказиб берувчи текшируви → ижрога қабул → етказиш → етказиб берувчи имзолаган далолатнома → маҳалла тасдиғи → бажарилган буюртма.
3. Q01–Q36 қабул синовлари, омбор қолдиқларини солиштириш ва имзолар текшируви бажарилади.
4. Шундан кейингина ишчи муҳитга ўтилади (8-бўлим).

Келишилган қарорга мувофиқ пилотда **камида икки маҳалла** қатнашади: иккинчи маҳалла бегона ҳужжатларга кириш тақиқини (Q20) текшириш учун зарур.

### 1.2 Муҳит

| Босқич | Муҳит | Маълумот |
|---|---|---|
| А. Пилот | **Синов сервери** | Ҳақиқий маълумотномалар нусхаси (маҳаллалар, бириктиришлар, каталог, календарь) ва синов буюртмалари. Синов буюртмалари ишчи муҳитга кўчирилмайди. |
| Б. Назорат остидаги бошланиш | **Ишчи сервер** | Ҳақиқий маълумотномалар, тасдиқланган бошланғич қолдиқлар, ҳақиқий фойдаланувчилар. Аввал пилот иштирокчилари, кейин қолган ташкилотлар уланади. |

Муҳим чекловлар:

- Имзонинг VPN'сиз (challenge) режими фақат намойиш ва синов маълумотлари учун ишлатилади. Ишчи муҳитда ҳужжат режими (сертификат занжири, амал муддати, бекор қилинганлик ва ваколат текшируви) шарт. Режим ҳар бир имзо ёзувида сақланади.
- `yashil_seed_demo`, `yashil_seed_load` ва `yashil_acceptance_protocol` буйруқлари ишчи серверда ишга туширилмайди (биринчи иккитаси синов маълумотини яратади, учинчиси алоҳида синов базасини яратади).

### 1.3 Тахминий муддат (таклиф)

| Давр | Давомийлик | Натижа |
|---|---|---|
| Тайёргарлик | 3–5 иш куни | 3-бўлимдаги шартлар бажарилган, `yashil_readiness --strict` хатосиз |
| Пилот сценарийлари | 10 иш куни | 4-бўлимдаги С-1…С-11 бажарилган, хатолар қайд этилган |
| Назорат ва тузатишлар | 3–5 иш куни | 5-бўлимдаги текширувлар, хатолар ёпилган, баённома |
| Қарор (go/no-go) | 1 кун | 6-бўлим мезонлари бўйича ёзма қарор |
| Ишчи муҳитга ўтиш | 2–3 иш куни | 8-бўлим қадамлари |

Жами тахминан 4 ҳафта. Аниқ саналар келишилгач шу жадвалга ёзилади.

### 2.2 Имзолаш ваколати

Модулга кириш фақат аъзолик орқали берилади («Маъмурият → Аъзоликлар»). Ҳар аъзоликда «Тайёрлайди» (`can_prepare`) ва «Имзолайди» (`can_sign`) белгилари ҳамда ваколат ҳужжати (рақами, санаси, файли) алоҳида сақланади.

| Кабинет | Имзоловчи нимани бажаради | Тайёрловчи нимани бажаради | Талаб |
|---|---|---|---|
| Маҳалла | Буюртманомани имзолаб юбориш; далолатномани қабул қилиб имзолаш | Буюртма ва қораламани тайёрлаш, иловалар, бекор қилиш сўрови | Имзоловчи профилидаги ЖШШИР сертификатдагига мос бўлиши керак |
| Ўрмон хўжалиги / ДМ | Далолатномани имзолаб маҳаллага юбориш; тескари операцияни тасдиқлаш; ДМ хизмат қувватини киритиш | Кўриб чиқиш, ижрога қабул, далолатнома тайёрлаш, кирим ва бошланғич қолдиқ, тескари операция сўрови | Ташкилот СТИРи киритилган бўлса, сертификатдаги СТИРга мос бўлиши керак |
| Уюшма | Имзо қўймайди | Кўриб чиқиш, юбориш, қайтариш, бекор қилишни тасдиқлаш | — |
| Кузатувчи | Имзо қўймайди | Тайёрламайди (тизим рухсат бермайди) | Кўриш ҳудуди: республика, вилоят ёки туман |

Ҳар пилот кабинетида камида битта **имзоловчи** бўлиши шарт. Суперадмин бошқа шахс номидан имзо қўя олмайди.

### 3.5 Тайёрлик текшируви

Барча бандлардан кейин платформа маъмури илова контейнерида ишга туширади:

```bash
python manage.py yashil_readiness                    # матн кўринишида
python manage.py yashil_readiness --strict           # блокловчи бўлса хато билан тугайди
python manage.py yashil_readiness --date 2027-01-11  # бошқа сана учун (масалан, янги йил календари)
python manage.py yashil_readiness --json             # баённомага илова учун
```

Текширув бўлимлари:

| Бўлим | Даража |
|---|---|
| Ўрмон хўжалиги бириктирилмаган маҳаллалар | блокловчи |
| Уюшма бўлинмасига йўналтирилмаган маҳаллалар | блокловчи |
| Жорий йил иш кунлари календари киритилмаган | блокловчи |
| Фаол каталог позициялари йўқ йўналишлар | блокловчи |
| Имзоловчиси йўқ маҳаллалар | огоҳлантириш |
| Имзоловчиси йўқ етказиб берувчилар | огоҳлантириш |
| Бошланғич қолдиқ киритилмаган ўрмон хўжаликлари | огоҳлантириш |
| Жорий ой учун хизмат қуввати киритилмаган ДМлар | огоҳлантириш |

**Пилотга кириш шарти:** `--strict` хатосиз тугайди (0 блокловчи) ва пилот иштирокчиларига тегишли огоҳлантиришлар ҳам 0. Бошқа ташкилотлар бўйича огоҳлантиришлар рўйхати ишчи муҳитга ўтиш режасига киритилади.

## 4. Сценарийлар

### 4.1 Синов маълумотлари

Пилот бошида ўрмон хўжалиги ва ДМ омборида қуйидагилар бўлиши керак (позициялар каталогдан танланади):

| Белги | Омбор | Позиция | Бошланғич ҳолат | Қайси синов учун |
|---|---|---|---|---|
| К-1 | Ўрмон хўжалиги | Кўчат (масалан, тут) | қолдиқ 100 | Q03, Q11 |
| К-2 | Ўрмон хўжалиги | Бошқа кўчат | қолдиқ 100 | Q12 |
| К-3 | Ўрмон хўжалиги | Мульча ёки бошқа кўчат | қолдиқ 0 | Q27, Q28 |
| Д-1 | ДМ | Органик ўғит (биогумус) | қолдиқ 0 | Q29, Q30 |

**Мезон:** «Яхлитлик: OK»; бузилган ҳужжат версиялари 0, ledger хатолари 0, йўқ файллар 0.

### 5.2 Омбор қолдиқларини солиштириш

1. Ҳар етказиб берувчи кабинетида «Омбор» жадвали: бошланғич, кирим, ажратилган, тикланган, ҳисоб қолдиғи, етишмовчилик. Ҳисоб қолдиғи = бошланғич + кирим (тескари операциялар билан) + бекор қилишда тикланган + омборга қайтариб олинган − ажратилган.
2. 4.1-жадвалдаги кутилган қийматлар билан солиштирилади: К-1 = 40 (кейинги буюртмаларсиз), К-2 = −10, К-3 = 50 (7.2 дан кейин, Q19 буюртмаси К-3 дан бўлмаса), Д-1 = кирим − ажратилган.
3. Кузатувчи «Омбор → ташкилотлар» рўйхатида етишмовчилик ва тасдиқ кутаётган тескари операциялар сонини кўради.
4. Тунги солиштириш вазифаси топган номувофиқликлар кузатувчига хабарнома сифатида келади — пилот давомида бундай хабарнома бўлмаслиги керак (ёки сабаби хатолар журналида изоҳланган).
5. Солиштириш натижаси етказиб берувчи вакили билан имзоланади.

### 5.3 Имзолар текшируви

1. Пилотда имзоланган ҳар тур ҳужжатдан (буюртманома, далолатнома) камида биттаси танланади. Бекор қилиш ҳужжати электрон имзосиз тизим ҳужжати (хэш билан муҳрланган) — у ҳам QR орқали текширилади.
2. PDF'даги QR код телефон билан очилади (логинсиз): ҳолат «Ҳақиқий», томонлар ва имзо вақтлари тўғри.
3. Эски версия QRи — «Алмаштирилган (эски версия)» (Q25).
4. Имзо режими текширилади: ишчи қабул учун имзолар ҳужжат режимида бўлиши керак (3.4-№4). VPN калити пилот вақтида ҳали бўлмаса, бу банд ишчи муҳитга ўтишдан олдин алоҳида такрорланади.

### 5.4 Захира ва тиклаш

```bash
./docker/prod/restore-test.sh                 # охирги соатлик захира
./docker/prod/restore-test.sh <ЙЙЙЙ-ОО-КК_СС>  # аниқ вақт белгиси
```

Скрипт ишчи базага тегмайди: вақтинчалик база ва папкага тиклайди, яхлитликни текширади ва захира пайтидаги бармоқ излари билан солиштиради. Ҳисобот `backups/hourly/restore-test-<вақт>.log` файлига ёзилади.

**Мезон:** захира ёши ≤ 1 соат (RPO), тиклаш вақти ≤ 4 соат (RTO), «Мос: захира ва тикланган маълумот бир хил».

### 5.5 Қабул синовлари баённомаси

Синов серверида (ишчи серверда эмас):

```bash
python manage.py yashil_acceptance_protocol --out yashil-bayonnoma.docx --environment "синов сервери" --json yashil-bayonnoma.json
python manage.py yashil_acceptance_protocol --out bosh-shakl.docx --no-run    # фақат қўлда тўлдириш учун бўш шакл
```

Буйруқ Q01–Q36 га боғланган автоматик синовларни алоҳида синов базасида ишга туширади ва DOCX баённома ёзади (ID, роль, кирилган маълумот, кутилган натижа, автоматик натижа, версия, сана). «Қўлда» устунини координатор 4-бўлим натижалари бўйича тўлдиради. Q35 ва Q36 автоматик синовга эга эмас — уларнинг натижаси 11.4 ва 5.4 ҳисоботлари билан илова қилинади.

### 5.6 Экспорт текшируви

Пилот охирида кузатувчи реестрни XLSX, CSV ва PDF кўринишида юклайди ва:
- қаторлар сони экрандаги реестр билан мос;
- йўналиш бўйича жами миқдорлар бирлик бўйича алоҳида, дубликатсиз;
- CSV UTF-8 кодировкада, Excel'да тўғри очилади;
- фильтр (давр, ҳудуд, йўналиш, ҳолат) экспортга ҳам қўлланган.

### 8.2 Орқага қайтиш

- **Имзоланган ҳужжатдан олдин** (биринчи ҳақиқий буюртма юборилмагунча): аъзоликлар нофаол қилинади, маълумотномадаги хатолар Маъмурият орқали тузатилади ёки маълумот охирги захирадан тикланади. Ўтиш янги санага кўчирилади.
- **Ҳақиқий ҳужжатлар имзолангандан кейин**: имзоланган ҳужжатлар ва операциялар тарихи ўчирилмайди ва қайта ёзилмайди. Модулдан фойдаланиш вақтинча тўхтатилади (аъзоликлар нофаол), очиқ буюртмалар ҳолати сақланади, тузатиш кейин давом эттирилади.
- **Нотўғри бошланғич қолдиқ**: ўчирилмайди — тескари операция (тайёрловчи сўрайди, имзоловчи тасдиқлайди) ёки кирим билан тузатилади.
- **Нотўғри бириктириш ёки йўналиш**: амал тугаш санаси билан ёпилади ва янги ёзув киритилади; эски буюртмалар ўзгармайди.
- **Маълумот бузилиши** (яхлитлик текширувида критик муаммо): база соатлик захирадан тикланади; тиклашдан кейин `yashil_integrity_check --compare <захирадаги JSON>` билан мослик текширилади. Охирги захирадан кейинги амаллар (≤ 1 соат) фойдаланувчилар билан қайта киритилади.
- Қоидаларни ўзгартириш (3/10 иш куни ва бошқалар) фақат янги амал санаси ва версия билан; илгари очилган буюртмаларга янги муддат қўлланиши алоҳида тасдиқланади (ТЗ §24.1).
